# termio 差异化、缺口与风险

> 综合各产品文档（[01](01-unpeel.md)–[08](08-warp.md)）的横向结论。

## 1. 已建立的差异化

1. **原生 + libghostty + 零配置状态盘 + 菜单栏托盘**：相比 Crystal（Electron）、claude-squad（TUI）
   占质感，相比 cmux（pane 边框环、无菜单栏托盘）占"环境氛围常驻"，相比 Vibe Island 那类外挂——
   termio 因拥有 PTY 而能**零配置**直出"需要你"。
2. **App 一等自动化的本地 git worktree**：cmux 的 worktree 只是"推荐模式"，termio 把它做成
   每会话自动建/隔离/清理的一等能力——这是 cmux 留下的明确空档。
3. **刻意不做 diff**：与 Conductor / Crystal / Cursor 形成清晰分界——更轻、更聚焦对话。
4. **本地优先、无账号、开源可定制**：对隐私/内网用户是硬卖点（Warp 的反面），
   且比 Unpeel（闭源单人）更可定制。

## 2. 能力缺口（按"护城河价值 / 实现成本"排序）

| 优先级 | 缺口 | 价值 | 参考实现 |
| --- | --- | --- | --- |
| **P0** | **逐轮 working（hooks 层）** | 让状态盘从"需要你"升级到完整"忙/完成/需要你"；成本低 | `Octane0411/open-vibe-island`（hook→socket→reducer）；每会话 worktree 已提供唯一 cwd 做关联 |
| **P0** | **Sessions MCP** | Unpeel 灵魂、cmux 仅 socket API；"Agent 编排 Agent"，成本中等 | `modelcontextprotocol/swift-sdk` + `iterm-mcp`/`libtmux-mcp` 工具集 |
| **P1** | **退出后会话不死（宿主进程）** | Unpeel/cmux 招牌；改造量最大 | `neurosnap/zmx`（基于 libghostty-vt）、`wezterm` mux-server、`dtach`、claude-squad 的 tmux 思路 |

建议顺序：先 hooks（小、立竿见影，补全状态盘）→ 再 Sessions MCP（中、护城河）→
最后 never-die 宿主（大、稳了 MCP 再啃）。

## 3. 风险

- **cmux 的声量碾压**：同基底、开源、YC、23k★，已验证品类。termio**不应在广度/声量上硬碰**，
  只守"有主见的极简 + 一等 worktree + 菜单栏氛围"。
- **品类被巨头吸收**：Cursor/VS Code 或 Warp 若把"多 Agent 会话盘 + 状态"做进主产品，
  独立工具空间被压缩。对冲：原生轻量 + 不绑账号 + 不做 IDE。
- **依赖单一上游**：`libghostty-spm`（个人维护的预编译 XCFramework）一旦停更受制；锁版本、关注活跃度。
- **Agent CLI 协议漂移**：状态检测依赖 Claude Code hooks / OSC 行为，Agent 升级可能改信号。
  **零配置（bell/OSC）层比 hooks 更抗漂移，应永远作为基线保留**。
- **"不做 diff"是双刃**：聚焦带来轻量，但部分用户想要 in-app 评审；用清晰文案把他们引导到
  "Agent 在代码里 + 用 git/IDE 审"，而非中途加面板破坏定位。

## 4. 一句话结论

termio 与 **Unpeel** 的差距只剩 Sessions MCP 与 never-die；与 **cmux** 的胜负不在广度而在
**"极简而有主见 + 一等 worktree 自动化 + 菜单栏氛围常驻"**。坚持「小而专、不做代码面板、
本地优先」是 termio 区别于所有竞品、且任何竞品都难顺手抄走的根本立场。
